# Recent AI sprite workflow research — checked 2026-10-07

Requested interval: **2026-08-07 through 2026-10-07**. Publication dates are separate from later page crawls. Tool/vendor guidance suggests experiments; it does not establish production quality.

- [Sprite Studio/Maker v0.3.3](https://github.com/JohnKinyanjui/sprite-maker/releases/tag/v0.3.3): release published2026-09-24, pinned source9de73a6136a1a045af2e8769349fbadc17dbef69; v0.3.2 was Aug19. Actual local probes exercised unchanged hierarchy/raster code and isolated native IK/mesh/skin modules with1vs8 Rayon workers. Rest pixels and repeated renders matched, but an extreme-fold fixture lost substantial arm coverage despite passing connectedness. This is a useful counterexample, not a whole-app benchmark, AI animation test or full application installation.
- [Makko Aug21](https://blog.makko.ai/how-to-make-ai-sprite-animations-that-match-the-rest-of-your-game/): keep an approved style/master/reference collection, inspect scale and identity drift. Vendor workflow guidance; no local service quality benchmark.
- [FrameSprite Aug22, updatedAug24](https://www.framesprite.com/guides/ai-character-consistency): fixed identity/palette/weapon reference, root alignment and frame/loop QC. Fold these checks into each candidate receipt instead of assuming generation consistency.
- [Bunraku v1 July29](https://arxiv.org/abs/2607.27348) is **outside** the interval. Ordered completed RGBA parts, alpha-derived mesh and learned poses are relevant older foundations; frontal/A-pose assumptions and layer-separation stress matter. [SeeThrough Feb3](https://arxiv.org/abs/2602.03749) is older too.
- [PixelLab current animation docs](https://www.pixellab.ai/docs/tools/animation) discuss skeleton/masked initialization and iterative manual correction; undated documentation must not be labelled a recent release. Neither it nor Google Imagen was quality-tested in this example.

Recommended experiment: fixed master→reviewed completed parts→limited deformation/rig→authored key poses→deterministic frame bake→localized pixel corrections→actual engine and temporal art review. Compare redraw, cutout, deforming rig and 3D routes on the same motion brief and ground/attachment measurements. Bounded searches did not verify a new editable-2D-rig paper within the interval; this is not evidence that none exists.

Technical foundations: [Godot2D skeletons](https://docs.godotengine.org/en/stable/tutorials/animation/2d_skeletons.html), [Viewport API](https://docs.godotengine.org/en/stable/classes/class_viewport.html), [Aseprite animation](https://www.aseprite.org/docs/animation/). Actual tested engine version/APIs outrank an outdated tutorial. Hardware acceleration is not established by a successful llvmpipe render.
