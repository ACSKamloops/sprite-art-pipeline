# Extend an approved character to new actions

Start with the user's exact approved clip and identity references, not a more convenient rejected variant. Keep source PNG bytes, native holds, camera, body scale, costume/material groups and acceptance scope pinned. An approved walk frame is an appearance reference; it is not automatically an approved idle/ready pose or a recovered rig.

Create a bounded action brief and source fingerprint before generation. Include the strongest keys, intended motion phases, grounded versus airborne root policy, equipment/motion profile, margins, entry/exit states and required evidence. Put unmade actions in a separate planned catalog; never bind them to a walk fallback and count them as covered. Version a queued job when its frozen references/brief changes. The atomic queue tracks leases/stages, not dependency scheduling; enforce neutral/ready dependencies explicitly.

Measure margins from all approved alpha bounds. An airborne body or extended fist can exceed a canvas that fit a walk. Add one declared constant padding transform or choose a larger fixed action stage; preserve painted scale. Align different-sized clips using their declared pivots. Do not fit, recenter or resize each pose independently. A nominal pivot is registration metadata, not a measured sole/contact point.

Author/review neutral/ready and extreme keys first. For an unarmed strike, check anticipation, coherent shoulder/elbow/fist travel, contact/follow-through, recovery and the neutral endpoint. For a jump, check crouch, takeoff, rise, apex, fall, contact, compression and recovery. Cloth/hair should follow the motion without changing identity. Existing visible cutouts can supply detail donors and small edits; new poses often require newly authored surfaces. They do not emerge from exact source segmentation alone.

Use a camera-matched continuous guide plus the accepted appearance when the provider supports both. Preserve the literal prompt, ordered media, model fields, submitted bytes and complete native return. Built-in ImageGen is also useful for key designs and bounded semantic repair. Whole-frame redraws can change limbs despite a preservation prompt; they need actual source comparison. Keep generation, fixed-canvas processing, precise pixel editing and final acceptance as separate steps.

Ground-plane motion and airborne height are separate. Runtime physics/contact should govern an interactive jump's apex/fall/landing state; a nominal storyboard tick is not proof the character landed. Prevent height being baked into frames and then applied again by the runtime. Keep the ground shadow separate. Attack active windows, collision volumes and cancel/completion events are authored gameplay data tied to visible frames, not properties inferred from a provider video.

For equipment, use the companion construction skill's `references/modular-parts-and-attachments.md`. Preserve body cels and add hand/grip transforms, compatible item variants, front/back pieces, hand-over-item masks and independent effects/damage tracks. Track persistent anatomical hand identities through occlusion. One-handed swings, two-handed swings and ranged releases need compatible body/grip profiles; attaching a sword to a punch does not create a slash. Unknown anchors stay unknown until measured and reviewed.

Validate exact source/alpha/clock/export invariants, every adjacency and entry/exit, then actual timed playback and engine events. Include held input, re-trigger, low-rate event crossings, forced interruption, active-window cleanup, recovery and restart. Check equipment instance lifetime and two-way swaps. Do not award art approval for source witnesses, frame counts or a successful importer. Preserve a human-approved baseline and keep new candidates separate until accepted.
