# Measured native motion references for Copper Scout

Run `python3 pilot/motion-reference/build_reference.py` from this worktree. It opens `qc/engine/motion-index/catalog-v1/motions.sqlite` read-only, binds four current route hashes, queries actor-slot-zero state, and samples the midpoint of every contiguous generic/script run. It independently reconstructs OAM tile alpha from raw VRAM and checks each tagged body's/weapon's native coordinates and flips. It separately reconstructs all 49 actual walk/Sword control-fixture frames from raw OAM/VRAM/CGRAM against the native golden PNGs. **695 checks pass**; no original pixel assets are exported for the new character.

The SQLite schema has routes, frames, actor_frames, selection_runs, method_hits and asset hashes. The public 85-route index contains charge and damage references, but no walk or normal far quick-Sword route. Those are supplied by the separate original-game control fixtures, not fabricated SQLite entries.

`reference.json` gives representative raw screen body/weapon alpha bounds, exact actor world/render reference and raw hashes. It uses only ownership records matched to actor-slot-zero native piece fields. Hardware OAM indices are not anatomical layer IDs; unmatched objects remain unclaimed. Alpha bounds alone do not identify boots, knees, foot contact, hand grip or limb alternation. Copper Scout needs declared authored landmarks and explicit equipment bindings for those checks.

Recommended adaptation: author compressed anticipation, a readable extended silhouette and a deliberate recovery; preserve the same original character parts/materials; animate planted-contact joints with IK and explicit root motion; use action-specific holds rather than force every clip into equal12frame timings. Keep the new rig's normal/charge/cast/damage/death/gesture state parameters separate from the original control fixture. Review silhouette and joint seams at1x/2x, then actual timed playback.
