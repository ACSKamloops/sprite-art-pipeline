# Bound native layered editor exchange

`construction_exchange.export_ase(store, project_id, output_absent_dir, animation=None)` writes `asset.aseprite`, `asset.aseprite.sprite-lab.json` and an exchange receipt. The output must be an absent absolute path; existing paths and symlinks, including parent symlinks, reject. Animation selection defaults to the original toolkit's first animation when omitted. Exporting files is not proof that a native editor opened them.

`import_ase(store, asepath, sidecarpath)` returns `project`, `project_hash`, `status='imported'`, `import_provenance` and the binding/raw-byte artifact IDs. It imports actual external RGBA edits without publishing a head. Native bytes may change; the complete sidecar metadata must match the immutable original Store binding. Import needs that binding and original project in the Store. For another Store, transfer the typed binding/project dependencies first; arbitrary self-declared sidecar hashes are not sufficient authority. Ordinary portable integral-decimal JSON spelling is normalized; changed metadata values reject.

The sidecar preserves original ticks/fps, loop, animation selection/sequence, events, landmarks, canvas pivots, palette entries/index aliases and untouched cel sharing. Tool milliseconds use cumulative boundary rounding and are checked against the original clock, never used to infer replacement timing. One/two/three ticks at60fps encode17/33/50ms; three repeated one-tick instances encode17/16/17ms. Both cases were checked by actual LibreSprite output. Events/landmarks remain metadata, not editor/runtime callbacks.

The ASE transport is **RGBA32, not native indexed ASE**. Unchanged pixel colors keep their original index aliases through the sidecar. A changed color maps to an existing exact palette entry or adds one. Untouched shared cel bindings remain shared; edits to individual external frame instances fork their original binding. Identical new pixel data does not prove intended source sharing. Conflicting edits to repeated instances of the same frame ID reject. Locked-layer pixel edits, renamed/reordered layers, changed canvas/frame structure, changed tool milliseconds and duplicate layer names reject. Masks, source ancestry and palette policies require explicit project/caller bindings; native RGBA does not infer anatomy or material ownership.

The bounded parser handles normal visible layers and full/cropped/linked RGBA cels. It rejects group/reference/background-special flags, opacity/blend/z-order transforms, nonunit pixel ratio, extra cel geometry, color profiles, tags, tilemaps and unrecognized chunks. Only the optional palette metadata chunks `0x0004` and `0x2019`, actually observed in LibreSprite1.3 output, are structurally validated then recorded as ignored. They do not supply indexed lookup for32bpp pixel data. This narrow handling follows the [official ASE file specification](https://github.com/aseprite/aseprite/blob/main/docs/ase-file-specs.md); it does not claim support for every Aseprite version or advanced feature.

Local limits are64MiB native input/output,16MiB sidecar,512 frames,128 layers,64million aggregate raw/full-canvas/link pixel work and64 metadata nesting levels. Parsed metadata is bounded iteratively before recursive canonicalization; decoder recursion failures become structured rejections. zlib inflation is limited to advertised RGBA bytes plus one, with EOF/trailing-data checks before image allocation. Reads use bounded regular-file descriptors; imports use a single frozen native/sidecar snapshot for validation, decoding, inventory and raw-byte provenance. Unknown/render-affecting chunks cannot become silently flattened success. Export source bytes are checked against the formatter's original hash before binding.

`validate_import_provenance(store, provenance_id, *, project_id=None)` checks typed shape/IDs, original/imported project and hashes, binding/sidecar/source-clock consistency, raw-blob existence and inventory geometry before a caller attaches it to a render. It does not authenticate a user-writable Store or rerun the pixel importer. An unchanged canonical raw project/hash reuses the original validated wrapper ID, retaining its `source_sequence` envelope and current history identity. Changed native pixels create a new project; include import provenance explicitly when rendering to retain original source ancestry, and create/rebase history deliberately rather than reusing an incompatible old current-project ID.

Bindings are `kind='construction-ase-binding'` with `project`, `project_hash`, `native_bytes`, `adapter_sidecar`. Import provenance is `kind='construction-ase-import'` with `source_project`, `binding`, `native_bytes`, `sidecar_bytes`, `imported_project`, `project_hash`, inventory and clock/sharing classifications. Raw blobs are raw bytes, not JSON documents. These references are separate from raw project metadata. `ExchangeError.to_dict()` includes `exchange_receipt`: a failed immutable Store receipt remains available even when native input/admission fails. The API does not invoke the editor; the retained tool runner separately records commands/exit/stdout/stderr before asserting success, including on failure.

Verification used actual installed LibreSprite1.3 batch open/save/reopen, without GUI visual review: two layers, three asymmetric frames, unequal ticks, source aliases, cropped/linked offsets, full source/composited RGBA and a partial-alpha one-instance pixel edit. Five batch commands in the final suite produced actual native files/PNG/JSON. No provider, credentials, art generation, native visual acceptance or private model was involved. Original toolkit hashes remain in `TOOLKIT-ORIGIN.json`; the safety derivative is separately bound in `ASE-PARSER-ORIGIN.json`. See `evidence/exchange/VERIFICATION.json` for exact code/tool/artifact hashes and selected results. Pillow deprecation warnings are retained; current operations pass, but future Pillow14 migration is not claimed.

Independent review found three original integration defects at84fa0dc: deeply nested sidecars leaked RecursionError before a receipt; boolean binding versionTrue passed import but failed its later validator; unchanged from-sequence imports lost their typed source wrapper ID. Owner correction3d322b9 adds iterative metadata bounds, a shared strict binding-shape validator and original-ID reuse. Dedicated regression controls pass. These defects were genuine; the earlier64-pass suite did not cover them.

The next independent pass also found that importing a binding with unrelated original native bytes or a wrong original project hash succeeded before its later provenance validator rejected it. Correctionc61a181 shares the semantic original-authority checks between both entrypoints before pixel import. The final owned69-test result and independent38-case selected pass supersede those limited earlier checks; they do not convert original failures into successes.
