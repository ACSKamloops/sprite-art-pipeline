# Planned whole-flow comparisons

This is the original pre-build comparison specification. Implemented subsets and outstanding cases are now tracked in [COVERAGE.md](COVERAGE.md); fresh execution evidence is generated by `scripts/verify_workbench.py`. The broader suites below are not all completed. All requests/artifacts must be frozen before a case starts. Retained target outputs are the first baseline; additional service calls must answer an unresolved named question and stay inside the existing budget. A successful subroutine is insufficient to pass the enclosing flow.

## F01 — import, reference preparation and guarded refinement

Use an asymmetric RGBA source, an alpha-zero pixel with nonzero RGB, partial-alpha pixels, disjoint material islands, separate layers and a second animation frame with a different duration. Run the entire import→per-adapter preparation→revision→inspection→reload→export sequence. Verify file versus decoded identity, frame/clock preservation, explicit hidden-RGB normalization, reference-slot order, selection/crop offsets and source return placement. Apply a simultaneous color map, current-state selection, guarded patch and pre-list snapshot copy in one ordered revision. Include a wrong expected color, invalid masked-out coordinate, excluded fill seed and too-large fill. Failed guards must preserve parent arrays and the revision graph under our declared local policy.

Retained baseline: `controlled-tests/pixel-guards/PIXEL-GUARD-RESULTS.md` and its49-call capture. Reuse the exact fixture and decoded goldens when its specification matches the local adapter. Do not infer all brush/outline/parser behavior from those cases. Separate technical failures from transport errors and downloadable candidates.

## F03 — source-bound pose methods and neural motion boundary

Use a labeled18-joint non-symmetric pose with explicitly different x/y/depth, rectangular dimensions and two template directions/tilts. Compare Lua and Godot projection/rank/truncation methods separately to independent analytic equations. Preserve16×9 versus8×9 searches, source tie ordering and catalog flip versus general flip. For the optional Lua auto helpers, start with valid wrapper input: a list of3Dframes, an explicit tilt/auto flag and a valid2Dreference array. The internal projector then creates the label-keyed dictionary consumed by ipairs; a dictionary passed as the outer frame input would test a different path. Also include TemplateSkeleton's raw3D nearest-search path and SkeletonBridge's name-versus-label mismatch. These should be source-compatibility controls, followed by a separately labeled corrected adapter—not silent fixes masquerading as parity.

For valid local model inputs, verify normalization, order, draw-depth versus optional public0..255 depth, source/output slot placement and supplied frames. The model result is a black-box boundary; joints do not prove rendered anatomy or motion fidelity. Missing template/gear assets must remain explicit. Retain source/output timing rather than inferring FPS from pose count. Only after the full workbench passes the preceding flows may the declared H3 comparison be added.

## Common acceptance record

Each case records specification/source versions, baseline hashes, observed request/preparation/output, traceable failure states, expected oracle, actual comparison, differences and review scope. Mechanical pass and visual approval are separate fields. Missing model/source/host evidence is `unsupported` or `unobserved`, never automatically `pass`. The local mechanical system is implemented in bounded subsets; broad full-flow conformance and the9/10 art result remain incomplete. Read the current coverage and exact run receipt rather than treating this original plan as an execution record.
