# Construction scope and finite analysis gate

The requested system is one local, reproducible workbench, followed by declared whole-flow comparisons. It is not a claim that PixelLab's private service has been recovered. The finite gate asks whether each named accessible client question has an answer and whether each inaccessible component has an explicit reconstruction decision. It does not ask for a fictitious semantic review of every line of the vendor's source tree.

The twenty-one original families retain all seven source-stage specifications. Transport, preparation and geometry overlays stay distinct. The public111 operations and captured101 MCP tools retain their exact source definitions: captured request schemas do not supply their handlers. The separate public guide has116named headings. The new source reviews qualify selected actual methods, rather than turning an inventory into approval.

The original18 source-authority questions are answered by the current transport, technique, geometry and host closures within their named source scope. Root must bind the latest corrected producer and reviewer hashes before allowing construction. Unobserved GPU, browser worker scheduling, native host affinity and provider durability become explicit comparison or adapter boundaries. Neural generation, learned interpolation/segmentation, private server ranking, arbitrary prepared-part constructors and incomplete formal draw-command documents remain unprovided. These must fail as unsupported or use a separately named local method with its own quality measurements.

The deterministic local workbench will include content-addressed RGBA and document storage; exact ordered edits with guards; preparation and source-specific pose math; owned layered scenes and deterministic keyframe animation; the recovered17-family offline VFX renderer; direction/state/candidate libraries; tiles/maps, supplied fonts and visemes; immutable jobs and revisions; editable manifests, sheets, animation codecs, review packets and Godot exports. Learned operations have capability adapters. No substitute may be advertised as the original model.

The actual source-backed VFX families are described in `analysis-models/depth-round3/renderer-completion/RENDERER-METHODS.md`. Pending G02 in the older worker report combines source and runtime questions: the17 dispatch bodies, reached materials/camera/light methods, controls, multi-direction packing and plain-sheet construction are already described in the renderer/root/export ledgers. Their complete numerical combinations, real browser Worker bootstrap and canvas codec behavior have not been tested. Source reconstruction uses pinned code and records that provenance; runtime coverage is added only by explicit comparison cases.

The build's entry boundary is import of supplied art, references, masks, strong poses, recipes, tile layouts, font files or viseme images. One image cannot supply missing back views, hidden surfaces or a learned temporal model. A useful editor must make those missing inputs visible while supporting exact fine edits, replay and comparison. Mechanical success is kept separate from the requested9/10 visual quality, which remains unachieved.

The eleven F01–F11 suites are the comparison plan. Building modules is authorized after the finite gate; target/model testing remains held until each enclosing flow is implemented and its fixture, oracle and acceptance record are specified. H3 is last. This scope supersedes the initial all-unreconciled placeholder audit while preserving it as history.
