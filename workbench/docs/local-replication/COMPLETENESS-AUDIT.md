## Finite stage that can complete

The proposed replay CLI is the right approach if it meets these gates:

1. Freeze exact channel/case IDs, input/fixture/code/schema hashes, expected values and mandatory versus optional checks. Keep the broader original63 and whole-flow ledger open where its authorities remain unprovided.
2. A read-only doctor reports selected dependencies and resource readiness. Python/NumPy/Pillow/jsonschema are core; Node and pinned renderer apply to F09; explicit licensed font bytes and FreeType apply where F08 rasterizes a font; an actual engine applies to required F10 checks. Missing components produce blocked/unsupported outcomes, not passes. No automatic install, network, credential/profile inspection or vendor forwarding.
3. Every recipe calls real local APIs, including F04/F05/F11 state and queue functions. Unsupported remote generation is a negative boundary, never replaced with a fake success. A local-service discovery route should describe the services actually bound by the host.
4. Retain immutable per-case receipts: inputs and tools, intermediate IDs, output encoded/decoded hashes, ordered frames/holds/play-count/pivots, exact assertions, failure classification and exit status. A directory or exit0 alone cannot be the oracle. Admission failure should still produce the replay-level receipt even if the lower pipeline has no run ID.
5. Preserve source masters and existing output directories. Direct plans can retain earlier publication after later failure; candidate-only jobs use guarded completion. Cooperative cancellation cannot force-kill a running subprocess, trusted handlers are not a sandbox, and failure may retain candidate files. Test the declared policy rather than promising universal rollback.
6. Optional supplied-input comparison requires a manifest for roles/order/direction, clock/play-count, pivot/crop metadata and pixel domains. Report rawRGBA, alpha, visibleRGB, palette and clock differences independently. Do not silently align, resize, trim, reorder or matte mismatches into a pass. Numerical equality cannot award motion/aesthetic quality.
7. Install the pinned wheel into an isolated target and execute the declared eleven channels outside the checkout. Package recipe/fixture/contracts/renderer data, and avoid an undeclared host font or absolute investigation path. Deliberately absent dependencies need honest outcomes. A wheel still depends on its stated Python/Node/engine environment; this is not a self-contained binary distribution.
8. After producer readiness, independently review fresh code/recipes and malformed/error/skip/preservation paths. Retain the exact code snapshot and independent outcomes; do not infer coverage from a channel counter.

A supported completion statement is: **“All required cases in the frozen F01–F11 local mechanical replay specification passed in the declared environment and installed package.”** It must retain a separate vector for required/optional coverage, unsupported formats, vendor parity, runtime/native observations and visual acceptance. It is not “PixelLab100% replicated.”

A useful humanoid comparison still requires approved directional source parts, hidden-surface art, strong poses/contact/event requirements, complete native-clock body-only and effects-on viewing, and two independent art/motion reviews. No diagnostic marker, source schema or mechanical pass provides those inputs. H3/provider work remains after its preceding frozen comparison prerequisites.

This report's method is source/AST and retained metadata inspection, not new runtime evidence. It names operational gates; implementation owners must provide fresh receipts before the next selected adversarial pass.
