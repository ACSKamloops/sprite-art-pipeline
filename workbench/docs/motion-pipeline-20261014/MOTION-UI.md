# Motion Lab UI

A separate `#motion` tab hosts the supplied-video workflow. This frontend is local orchestration, not a recovered private PixelLab sampler, cutout or generation implementation. The original source-effects tab behavior is unchanged.

## Explicit workflow

- Load a retained native example, or upload at most64MiB of video bytes and explicitly decode them. The unchanged source video has native browser playback controls. A separate decoded-frame inspector shows native index, integer PTS/time base/origin and rational source hold.
- Declare JSON indices, positive rational holds, one role string per pose and an explicit loop checkbox. Initial arrays are empty. Choosing all indices, appending the inspected index, deriving holds from source PTS and filling neutral roles are separate user actions. Roles are annotations; no hit/contact events or automatic phase selection are invented. The PTS helper uses checked BigInt arithmetic and reduces fractions; its last selected pose holds until the admitted native end.
- Create a sampled sequence. Candidate preview and its declared clock remain separate from the unchanged native video. Candidate one-shots stop on the final pose and require Restart; repeating is explicitly authored.
- Optionally create a conditioned draft: default background/palette are keep. Output size is explicitly selected as native or fixed256square. Recovered-host seed/tolerance selection and calibrated fixed reference palette are opt-in, visibly labelled fallible local methods. Neither missing sword pixels nor private temporal de-flicker is reconstructed.
- Import the current candidate into Studio explicitly. Hidden-RGB normalization is unchecked by default and passed literally to `local.studio.from_sequence`. The fresh-import result uses Studio's proven positional mapping through `loadResult`; it does not infer source alignment from an arbitrary Workspace order.

Sample declarations invalidate downstream candidates. Conditioning changes invalidate the conditioned candidate; a new sample or conditioning action is required before import. Epoch checks discard delayed results after declaration changes. Browser restore retains declarations, immutable artifact IDs, current candidate and prepared/submitted packet IDs; it does not start video playback or provider operations. Preview clock execution is a browser float projection of retained rational holds, not a recovered provider FPS or visual acceptance proof.

## Generation pane

Upload first PNG bytes and an optional last PNG, or explicitly select last=same bytes as first. Preserve the literal prompt, including whitespace. Duration4–15seconds and768P/2K are declared controls. Prepare calls only `local.motion.prepare`; packet identity and receipt are inspectable. Submit, Poll once and Download returned video are separate buttons. Download places the returned media ID in the native-source field; decoding remains manual.

Submit is disabled unless the server catalog enables it. A submission attempt is persisted before awaiting its response; the UI will not resubmit that packet automatically, including after an ambiguous failure or browser reload. The server remains authoritative for duplicate/paid-action guards. Editing request fields invalidates the prepared packet. A separate submitted-history selector retains the latest32IDs and bounded last-action/status labels. It can explicitly resume an immutable old packet for poll/download; it labels that request as separate from the editable draft and never resubmits it. No timers, automatic polling, retries, hidden model calls or credentials are introduced.

## Preloaded canvas correction

The first integration exposed a material preview limit: assigning a new PNG URL on each hold could leave an old image displayed while the server encoded/transferred/decoded the next image. This especially affects an authored1/60-second strike. Candidate preview now loads and explicitly decodes every ordered candidate raster before committing the preview or enabling playback. Repeated raster IDs reuse a decoded image while preserving every ordered index and hold. The canvas keeps ID `motion-candidate-frame`; each timed draw synchronously clears and draws the already decoded full-canvas image with smoothing disabled. Playback performs no network/decode operation per hold.

The aggregate declared candidate canvas area times frame count is capped at16,777,216pixels. An over-limit preview is cleared and reports: choose fewer poses or explicitly create a256square conditioned preview. Sampling artifacts remain retained, and conditioning remains available from the sampled sequence. No trimming, deduplication of timeline entries, implicit resizing or silent fallback is performed. Canvas-size mismatches reject the preview.

A per-preview ticket and declaration epoch discard late image results, including stale load errors, so an older preload cannot replace the current candidate. `motionUI.renderCandidateFrame(index)` provides explicit paused frame inspection through the same draw path. `motionUI.getPreviewState()` returns copied holds, canvas dimensions, selected/rendered frame and loaded-frame count; the canvas also records `data-rendered-frame` for deterministic QA. These methods do not imply that a busy browser scheduler can present every1/60-second pose; timed frame presentation still requires its own evidence.

Additional actual Chromium verification passed against mocked local artifact transport: two real opaque red/blue PNGs at stored holds `[1,60]`/`[1,60]` both decoded before preview; deterministic RAF advancement across16.7ms drew the blue pose; explicit inspection redrew red; request count stayed unchanged during playback; a deliberately delayed old red/blue preload could not overwrite a newer green candidate; and a32M-pixel declaration rejected before loading images. No page errors occurred. This is real browser PNG decoding/canvas readback plus a controlled clock-boundary test, not natural-scheduler smoothness or live backend acceptance. ## Prepare discovers retained provider state

Preparation now consumes the actual safe snapshot fields returned by `motion_provider.packet_status`: packet, status, submission_attempts and task_id. Only an explicitly verified `prepared` snapshot with zero attempts and null task is eligible for Submit; remembered local attempts continue to block it. Missing/unknown/malformed safe state never enables submission. A task ID or any attempted/non-prepared state records the immutable run in the bounded resume history, shows its actual status/task ID and leaves resubmission disabled. Prepare does not submit or poll that existing run.

An unsubmitted packet restored from browser storage requires an explicit Prepare again to refresh safe status before Submit. This avoids presenting a stale browser snapshot as current server authority. Submitted history still restores for manual resume/poll/download. Those actions remain explicit; no provider operation is triggered by state discovery or reload. ## Download-to-decode producer binding correction

A later flow audit found that the initial UI kept only the downloaded media ID, so ordinary Decode could lose native-video/download receipt provenance even after the backend extraction-closure fix. Prior0.8.0 browser proof remains unchanged: its16pixel/hold identities and386listed ZIP hashes do **not** certify full producer request/receipt closure. Final0.8.1installed QA is pending a rebuilt runtime containing this UI correction.

The UI now stores exactly `{media,native_video,download_receipt}` after Download. All three IDs are strict artifact IDs; both referenced documents must have the correct kind/version and match the returned media and current packet. Incomplete, malformed or mismatched responses reject admission rather than silently retaining an unbound media ID. Decode forwards both producer IDs only when the binding matches the current media field; the server independently validates those references.

Binding state persists across reload and same-media extraction restoration. Raw upload, manual media choice and a new packaged example explicitly replace it. Newly admitted media also detaches an older extraction, fixing a related reload defect that could overwrite a pending downloaded/uploaded blob with the previous source. A malformed stored binding blocks Decode and retains that diagnostic across reload until the user explicitly chooses a source again or re-downloads; it does not silently downgrade to raw admission.
