# Recovered PixelLab VFX services

`bind_source_vfx(registry, store)` adds `local.pixellab.vfx.describe`,
`local.pixellab.vfx.validate`, `local.pixellab.vfx.controls`, and
`local.pixellab.vfx.render`, classified
`deterministic-source`. These are local adapters to retained website factories;
they make no current MCP, private server, neural generation, or character
animation equivalence claim. No generated substitute algorithm is supplied.

`describe({})` executes factory `47381`, reading its original `CW` common field
table, `Nk` family tables (17), and `E5` ramps. The adapter converts each original
tuple to `{type, required, default, bounds}`. A source Symbol default means
required and is represented by `required: true, default: null`; other null
defaults remain optional. This is a presentation conversion, not a new validator.
Concrete original preset recipes have not been extracted by this change:
`presets` is empty, with an explicit explanation. Existing mechanical fixture
recipes are not promoted to source presets.
The integration task can separately publish verified retained provider preset
responses with their request/response provenance.

`validate({recipe})` calls original `47381.W$` and returns its normalized `recipe`.
Unknown constructors, fields and invalid bounds are rejected by that original
normalizer. Its own supported animation expressions, layer branches, ramps and
control validation remain source code. No clamping or fallback is added.

`render({recipe, subject?, images?, timeout?, values?})` validates through the
original normalizer and passes the raw recipe to the existing pinned original
renderer `39852.sY`, returning immutable sequence IDs and executed module IDs.
When `values` is supplied, `source_controls.render_controlled_effect` handles the
control updates; that module must be installed alongside this service.

**Normalized recipes are not renderer input documents.** The source normalizer
inserts `rng: null` into ordinary layers, but its input validator rejects an
explicit null rng. Rendering the normalized output therefore fails. The adapter
retains raw input for execution; source controls must likewise retain the raw
declared recipe after value updates. Applying controls to a preview and rendering
that preview would also apply mul/add binds a second time. Both boundaries are
visible in the original source behavior, not corrected with invented algorithms.

The shared helper `run_source_vfx('apply_controls', recipe, values)` clones raw
JSON, replaces supplied matching control values, calls `W$` then original `uY`,
and returns raw `declared_recipe`, `normalized_recipe`, applied `recipe`, and
normalized `controls`. Unknown control IDs are rejected by a labelled local
wrapper guard. Input objects are not mutated. Omit `values` or pass an object.

Provenance is included on successful calls and registrations: original bundle
paths and SHA-256, extracted factory SHA-256, UTF-16 start/end offsets, manifest
identity and actual executed module IDs. The manifest is pinned to
`188743c8078e006117a6cbc51fdf96a73cafecc387a1a998276d93aa8d19645f`.
`47381.js` is pinned to
`f132d2179dc95ce9079d56b14e10434d2ed2512120098cd90f037671feeaff9c`
and retains create-vfx bundle UTF-16 offsets `[35289, 78121)`.
The Node loader verifies loaded factories; Python checks every manifest factory
before invoking the new service. The new runner, VM loader, serialization,
resource budgets, registry, and content-addressed storage are local wrappers.

Local limits remain explicit: metadata calls use 2 MiB JSON, 256 MiB Node heap,
and 30 seconds; rendering uses the pre-existing 16..512 pixel side profile,
1..32 frames, at most 128 layers and 2 MiB recipe JSON, at most 64 source images,
8 MiPixels aggregate source raster budget and at most 120 seconds. Validation
alone uses the original canvas range, which extends to 1024; it does not promise
the wider recipe is renderable within the local rendering profile.

`tests/test_source_vfx.py` checks original export tables, original normalizer
defaults and rejection branches, hash enforcement, and all 17 source-family
fixture pixel hashes through registered rendering. These are mechanical source
receipts; they establish no artistic acceptance or general provider parity.
Integration must include `source_vfx_runner.cjs` as package data. Existing root
registry/server/UI bindings are intentionally owned by the integration task.

The Source view also offers a separate observed prepared-default library. These
105 recipes are retained, already fitted instances of owned `add_part` executions;
they are not the private prepared constructors. The two `get_preset` snapshots
keep their original IDs and file pin. `OBSERVED-VFX-DEFAULTS.json` contains only
the returned recipe and concise response, input-binding, native atlas, source
manifest and per-frame comparison hashes. It contains no response storage links,
browser state or credentials. Its own file pin is enforced before selecting data.

Use `local.pixellab.vfx.observed_catalog`, `observed_default` with `{"id":
"observed.alert_pop"}`, or `render_observed` with the same ID and optional
`values`/`timeout` or supplied `subject`/`images` Store IDs. These methods are available through HTTP, the JSON Lines
channel and `pixellab-vfx` CLI. The Source view groups the observed instances
separately and exposes each original slider, ramp, toggle and select declaration.
The observed render job keeps the library observation receipt in sequence
metadata alongside the unchanged renderer and control receipts. Changing the
recipe text moves the render to the ordinary raw-recipe path. Three transparent
subject-dependent defaults are marked as needing subject setup. A raster alone
does not configure a subject: the source renderer also requires a `subject`
declaration in the recipe. The observed path never silently invents one. Observed
receipts distinguish captured default inputs from locally changed controls or
supplied subject/image inputs.

The retained default comparison proves exact pixels for these captured instances.
Editing a declared control executes the original local control functions; it does
not establish off-default server equivalence, new fitting, arbitrary part
composition or the current server implementation. Atlas export durations use
integer milliseconds while the source recipes retain their declared FPS.

Three separate subject examples retain the actual MCP-returned setup for
`burning_edge`, `hurt_flash`, and `sprite_dust`. They use one unchanged own R9
PNG, packaged with its hash. Selecting an example imports that raster into the
Store and replays its original declared recipe; it does not add a guessed subject
placement to the 105 defaults. Subject example pixels have separate native/source
comparison hashes. Exact reproduction does not imply a strong or visually
approved effect: the captured burning-edge default is subtle.
