## Remote processing boundaries and response policy

- **Transparency/background removal:** Lua `generate-remove-background.lua:69–95` submits source bytes to remote `remove-background`. “Simple” maps to `remove_simple_background`; “Complex” maps to `remove_complex_background`; only Complex retains text. Godot `ui/tools/RemoveBackground.gd:69–120` submits the same task names, sends null text for Simple and routes to the service. Neither implements foreground segmentation, black-key reconstruction, matte refinement or cutout neural weights. The existing local H3 border-connected key remains a separately authored approximation and is not this source algorithm.
- **Palette enforcement:** Godot `QuantizeColors.gd:289–340` submits image arrays to `quantize-image`, with automatic mode omitting palette/target, explicit `num_colors`, or RGBA `palette_image` and its dimensions; selected dithering sends numeric index and strength. `384–404` builds a Palette from unique colors in a returned image, including alpha distinctions; it does not calculate a reduced image. Placement at438 onward recomputes current selected frames/layer; no independent palette-membership check or local repair is established in that branch.
- **Different interfaces must stay different:** Lua `quantize-image.lua:329–383` maps dithering sizes to 1/2/3, emits a request per selected frame, and divides configured strength by 10. The public OpenAPI `/reduce-colors` takes PNG image arrays, string dithering (`none`,2×2,4×4,8×8) and `dithering_strength` 0–10. Its contract says all images are jointly reduced onto one palette. Legacy `quantize-image` request-per-frame behavior is not proof of that public multi-image policy or equivalent parameter units.
- **Response preference is not processing:** generic Godot `websocket.gd:169–210` initially selects main `images`/`image` for bookkeeping and slicing, then preferentially draws `quantized_image`/`quantized_images`. With both arrays, skip logic slices main images and leaves quantized array untouched; this existing static branch finding is retained, not claimed fixed. Background dispatcher266–325 instead draws `images`, reports `original_images`, and slices both in its guarded path; that second behavior was replayed above. The website animation bundle also chooses `quantized_images || images` during progress/completion. These branches consume remote results and do not reveal how they were generated.
- **Public declared de-flicker:** retained `evidence/openapi.json`, SHA256 `af8ddcf710e1044455a31f091500f4381d2c89da667b2751744f734520ae93ec`, JSON pointer `/components/schemas/AnimatePixminimaxRequest/properties/drift_threshold`, declares nonnegative sensitivity, comparison to the first frame, zero correcting every frame and omission using a default. It does not supply the default, foreground mask, drift metric, color space, correction function, temporal window or weights. `/AnimateWithTextV3Request/properties/drift_threshold` has corresponding prose.
- **Client omission/default:** Lua `generate-animate-pixminimax.lua:17–34` and Godot `AnimatePixminimax.gd:316–323` expose `no_background`, not an explicit drift-threshold override. The term scan found no `deflick`, `de_flick` or `drift_threshold` in 112 Lua files, 126 extension Godot scripts, 105 website JS chunks or the one shipped editor bundle. Absence of those names is scoped negative evidence, not proof against obfuscated, differently named or server-side smoothing.

Public OpenAPI also states `no_background=true` cuts out an opaque first frame before animating, and `/unzoom` composites alpha onto white and returns opaque output. These are **declared service policies**, not recovered executable implementations. The docs describe auto/exact palette counts and ordered dithering; they do not reveal its clustering or matching implementation. Parent's separate black-box response experiments may constrain those methods but are not executed or independently validated by this report.
